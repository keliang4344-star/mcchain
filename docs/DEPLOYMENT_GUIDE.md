# MC 公链（MobileChain）主网运维指南 · 多客户端与云端分散

> 适用范围：主网上线前的生产级部署与日常运维。
> 关联架构决策：多客户端/云端分散为主网 P0 硬要求（防单点故障，借鉴历史链单客户端宕机教训）。

## 1. 为什么必须多客户端 + 云端分散

| 风险 | 单点后果 | 分散后表现 |
|---|---|---|
| 单客户端实现缺陷（共识/状态机 bug） | 全网停摆或分叉 | ≥2 套独立客户端互为校验，一方异常不拖垮全网 |
| 单云厂商故障（网络/机房/账号封禁） | 验证人集体离线、共识中止 | ≥3 家云厂商分散部署，单家故障其余继续出块 |
| 单一私钥保管点泄露 | 验证人密钥失窃被 slash | 双签保护 + 冷热分层 + 多云多签 |

## 2. 客户端多样性（Validator Client Matrix）

- **要求**：主网至少运行 **2 套独立实现的验证人客户端**，互不共享代码路径与依赖。
- **本仓库现状**：`mcchaind` 为唯一实现（Cosmos SDK v0.47 + CometBFT）。第二客户端计划：
  - **选项 A（推荐）**：以 CometBFT 兼容的备选共识层客户端 + 同一状态机（go 模块复用），覆盖共识层单点。
  - **选项 B**：等待生态基于 Cosmos SDK 的替代节点实现（如 `simd` 类）成熟后接入。
  - **过渡措施**：上线初期以 ≥3 家独立机构各自编译、各自签名运行 `mcchaind`，配合**版本锁定与二进制哈希公示**，把"同一代码多机构运行"作为过渡，目标仍是 2 套独立实现。
- **验证人要求**：各验证人必须使用**不同的构建来源**（至少两家机构自建 CI 产物，禁止全员下载同一发行包）。

## 3. 云端分散（≥3 家云厂商）

- **硬要求**：主网验证人基础设施至少覆盖 **3 家云厂商**（或 2 家云 + 1 家自有机房），禁止单云承载全部 2/3 以上验证人。
- **推荐拓扑**（单验证人）：
  ```
  主节点（signer）  — 云 A（如腾讯云），仅出块，跑 P2P 网关
  哨兵节点 ×2       — 云 B（如 AWS）、云 C（如 GCP），只连主节点，对外提供 P2P
  冷备节点          — 本地/私有机房，实时同步快照，不参与共识
  ```
- **哨兵架构**：验证人节点不直接暴露 P2P 公网端口，通过 2 个哨兵代理，隐藏验证人 IP（防 DDoS 直打）。
- **快照与恢复**：每 500 块对验证人数据做一致性快照，冷备节点定时同步；恢复目标 < 15 分钟。

## 4. 密钥管理（验证人私钥）

- **主密钥**：验证人私钥仅存于主节点 signer 进程，物理机或 HSM/云 KMS 签名（`--priv-validator-laddr` 远程签名亦可）。
- **双签防护**：启用 CometBFT 内置的 double-sign 检测 + 本项目 slash 模块的 tombstone 机制（双签即永久拉黑），配合**护栏**：检测到高度落后即停止签名（`--halt-height`）。
- **多签治理密钥**：治理主体密钥用阈值多签（≥2/3），分散于 ≥3 家机构，禁止单人或单设备持有全部。

## 5. 备份与灾难恢复（DR）

| 项 | 频率 | 说明 |
|---|---|---|
| 验证人 `priv_validator_key.json` | 生成时 | 冷备份 ≥2 份，异地保存，物理隔离 |
| 最新区块快照 | 每 500 块 | 冷备节点 + 对象存储（跨 2 家云） |
| 创世文件 + 升级二进制 | 每次升级 | 哈希公示，双渠道发布 |
| 配置（app.toml/config.toml） | 每次变更 | 版本化入库，回滚即用 |

**DR 演练**：主网上线前至少完成 1 次全流程演练（主节点物理销毁 → 冷备接管 → 恢复出块 < 30 分钟）。

## 6. 监控与告警（运维必配）

- 指标：区块高度停滞、P2P 对等节点数、内存/磁盘、signer 心跳、gas 均价。
- 告警阈值：高度停滞 > 60s、对等节点 < 5、磁盘 > 85%、signer 无心跳 > 2 个区块。
- 本项目 telemetry 指标已就绪（`tokenomics.*`/`dex.*`/`liquidstaking.*`/`referral.*`/`mcchain.*`），接入 Prometheus + Alertmanager。

## 7. 上线检查清单（Checklist）

- [ ] 2 套独立客户端编译源（或 ≥3 家机构独立构建同一客户端）
- [ ] 验证人分布在 ≥3 家云厂商
- [ ] 哨兵架构部署完成，验证人 IP 不公开
- [ ] 私钥冷备份 ≥2 份异地 + 双签防护启用
- [ ] 快照/冷备节点运行中，DR 演练通过
- [ ] 监控告警全部生效，值班 on-call 就位
- [ ] 升级流程（二进制哈希公示 + 多签提案）验证通过
